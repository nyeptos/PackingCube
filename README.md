# PackingCube

Minecraft **1.21.1 / NeoForge 21.1.264 / Java 21** 向け、モジュール式バッグMODの最初の動作確認版。

## この版でできること

- 大型バッグ：フィルターバッグ装着用9枠。通常アイテムは入らない。
- フィルターバッグ：9枠。単体でも右クリックで開く。
- フィルターバッグを大型バッグへ入れると、地面から拾う対象アイテムを自動収納。
- タグ／個別アイテムによる指定。共通のタグ・アイテム指定に対して「含む」「含まない」を切り替える。
- Curiosあり：Big Bagのみ`back`枠へ装備可能。装備中のバッグ→通常インベントリ位置順、各バッグ内の左から右へ振り分ける。
- 満杯なら次のバッグ、その後は通常インベントリ。どこにも入らなければ地面に残る。
- 中身とフィルターをアイテムのデータコンポーネントへ保存。
- バッグの入れ子を制限。大型バッグにはフィルターバッグのみ装着可能。

変更ファイル一式を、既存プロジェクトの同じ場所へ上書きする。
**ひな形の `src/main/java/github/nyeptos/packingcube/Config.java` は削除する。**

## ゲーム内で試す

テストワールドのクリエイティブタブ「PackingCube」から両バッグを入手する。
または以下のコマンドを使う（`/give` は通常の権限が必要）。

```mcfunction
/give @s packingcube:large_bag
/give @s packingcube:filter_bag
```

1. フィルターバッグを**メインハンド**に持つ。
2. 以下で対象タグを指定する。`/packingcube` は自分のバッグだけを編集し、チート権限は不要。
3. 大型バッグを持って右クリックする。
4. フィルターバッグを大型バッグの上段へ入れる。
5. 画面を閉じ、大型バッグを通常インベントリに入れた状態で対象アイテムを拾う。
6. 通常画面で**C（ラジアル用キー）を押して開き、バッグの方向を左クリック**すると開く。キーを離しても決定しない。数字キー1〜9でも選択可能。
7. モジュールを取り外す場合は左クリック、またはShiftクリックで移動する。

```mcfunction
/packingcube filter tags minecraft:logs
/packingcube filter exclude_items minecraft:oak_log
/packingcube filter items minecraft:diamond
/packingcube filter exclude_tags minecraft:planks
/packingcube filter show
/packingcube filter clear
```

- 「含む」モードでは対象タグと個別アイテムはOR条件。いずれかに一致するものだけ収納する。
- 「含まない」モードでは除外タグ／個別アイテムに一致しなければ収納する。同じ登録リストを使い、判定だけを反転する。
- 存在しない個別アイテムIDは拒否する。タグは将来のデータパック用指定も保存できるが、存在しない／空のタグは一致しない。
- フィルター変更・解除は中身を変更しない。
- コマンドで編集する場合は、バッグ画面を閉じ、モジュールを取り出して手に持つ。GUIなら装着したまま編集できる。
- フィルターは**自動収納と手動収納の両方**に適用。既存の対象外アイテムは削除しない・取り出せる。

## 暫定仕様・未実装

以下は完成仕様ではなく、最初の検証のための割り切り。

- 大型バッグは通常インベントリ36枠、またはCuriosの有効な`back`装備枠で動作。Filter Bag本体はCurios装備対象にしない。
- 複数所持時は装備中→通常インベントリの順。複数のback枠がある場合はスロット番号順。優先順を変える専用UIは未実装。
- GUIは専用メニュー・専用画面。スロット制限をクライアントとサーバーで共通化。背景とアイコンのみ、バニラ素材を仮使用。
- 円形メニューを実装済み。廃棄・自動補充・レシピ・構成一括交換は未実装。
- 開いている大型バッグ（内部モジュールまたはラジアル選択中も含む）は、競合防止のため一時的に自動収納から除外。画面を閉じると再開する。
- 開いているバッグ本体は移動可能。手元から離れた場合は編集を終了する。
- チェストからの取り出しや手動移動は自動振り分けしない。
- バッグへ直接収納した分について、他MOD向けの拾得Postイベント互換性は未整備。通常インベントリへ入る残数はバニラ処理に任せる。
- 通常インベントリのバッグは通常の所持アイテムと同じ死亡処理。Curios装備中はCurios側の死亡時設定に従う。中身を個別に地面へばらまく機能はない。
- 専用バッグの容量は仮。モジュール数・容量のバランスは未調整。

## フィルターGUIの使い方

1. 単体のフィルターバッグ、または大型バッグ内のフィルターバッグを開く。
2. 右上の「フィルター」を押す。アイテムをカーソルに持ったままでも開ける。
3. 通常の操作でアイテムをカーソルに持ち、右側の見本スロットをクリックする。見本にはコピーだけを登録し、元のスタックはカーソルに同じ個数で残る。
4. 右側で「含む」または「含まない」の動作モードを選ぶ。
5. 個別指定なら「このアイテムを登録」。タグ指定なら「タグ候補」の一覧で `+ #タグID` を押す。
6. 「登録済み」から設定一覧を確認し、`×` の行を押すとその条件だけ削除できる。
7. 「戻る」で通常の収納操作へ戻る。

- 設定画面でも実スロットは通常どおり収納・取り出し可能。見本登録は右側の専用見本スロットで行う。
- 見本スロットを右クリック、または空カーソルで左クリックすると見本を解除する。バッグ自体は見本にできない。
- 設定は即時保存。保存ボタンや確定操作は不要。
- 装着中モジュールも同じ操作で設定できる。取り外す必要はない。
- 候補と登録一覧はID検索・ページ送りに対応。
- タグ候補にカーソルを合わせると、完全なID、対象種類数、対象アイテムの例を表示。
- GUIから追加できるのは、その見本アイテム自身、またはそのアイテムが持つタグ。
- 任意のタグIDの直接登録は既存コマンドを使う（GUIの入力欄は検索用）。
- 個別アイテム指定はアイテムID単位。エンチャント・名前・その他コンポーネントの完全一致指定ではない。
- 保護上の上限は1バッグにつき合計256条件。重複登録は増えない。
- 見本と表示用データは保存対象ではない。バッグ画面を閉じると見本は破棄される（アイテムの増減はない）。
- テクスチャ画像・モデルJSONはこの変更では触っていない。

## 排他的なフィルターモード（最新仕様）

| モード | 収納条件 | 有効側の登録が空の場合 |
|---|---|---|
| 含む | 共通リストのタグ／アイテムのいずれかに一致するものだけ | 何も入らない |
| 含まない | 共通リストのタグ／アイテムのどれにも一致しないものだけ | 入れ子禁止などの共通制限を満たす全アイテム |

- 新品およびクリア後の初期状態は「含む・未登録」。
- 登録リストは一つだけ。切り替えてもタグ・アイテムの指定は変わらず、判定だけが反転する。
- GUI上の「含む／含まない」は一覧のタブではなく、バッグの動作モードを切り替えるボタン。
- クライアントの仮判定とサーバーの確定判定を一致させ、手動クリック・ドラッグ・数字キー交換・Shift移動にも適用する。
- Shift移動では、既存の対象外スタックへ合流させるバニラの経路も拒否する。
- 設定変更で対象外になった収納済みアイテムはそのまま残り、取り出せる。
- 「含まない」で対象外にならなくても、バッグなど禁止された入れ子は収納できない。
- 旧版のモード情報がないデータは「含む」として扱う。旧版の含む・含まない両リストの指定は共通リストへ統合し、重複は一つにまとめる。

コマンドでモードを切り替える場合：

```mcfunction
/packingcube filter mode include
/packingcube filter mode exclude
```

`tags` / `items` は共通リストを編集する。旧 `exclude_tags` / `exclude_items` コマンドも互換用の別名として同じリストを編集する。
コマンドで条件を追加しただけではモードを変えない。`show` は現在のモードも表示する。

## 最新修正：モード共通の指定リスト

例えば「鉱石タグ」を登録した場合：

- 「含む」なら、鉱石タグに一致するものだけ収納。
- 「含まない」へ切り替えると、同じ鉱石タグに一致しないものだけ収納。
- 「含む」へ戻しても、鉱石タグの指定はそのまま残る。

検索文字・一覧ページもモード切り替えだけではリセットしない。
旧版で両リストへ登録していた場合は、両方を合わせた指定が表示されるので、不要なものだけ削除する。

## 開いているバッグ本体の移動

- バッグを開いたまま、本体をカーソルで持ち、通常インベントリ内の別スロットへ置ける。
- 数字キーによるホットバー交換、オフハンド交換にも対応。
- 大型バッグ内のモジュールを開いている場合も、親の大型バッグを移動できる。
- カーソルに本体を持っている間も画面を維持する。アイテムを持ったまま設定編集も可能。
- バッグを投棄するなど、通常インベントリ・装備・オフハンド・カーソルのいずれからも見つからなくなったら画面を閉じる。
- 開くたびに本体へ追跡IDを付け、ItemStackがコピーされる移動にも対応する。
- 同じ追跡IDのコピーが複数見つかった場合は、誤ったバッグへ書き込まないよう編集を終了する。
- バッグ自身を内部へ収納することは引き続き禁止。
- 開いている大型バッグへの自動収納一時停止は、位置を変えても継続する。

## 最新操作：非消費の見本スロット

1. フィルター設定画面で、アイテムを通常のスロットからカーソルに持つ。
2. 右側の見本枠へ左クリックで置く（ドラッグして見本枠へ離す操作にも対応）。
3. 見本枠には1個表示のコピーだけが入り、元スタックの個数は減らない。
4. 元スタックを通常のスロットへ戻す。戻す前にルールを登録してもよい。
5. 以後のタグ候補・個別アイテム登録は、その見本から行う。

右クリックで見本のみ解除。見本の置き換え・解除によるアイテム返却は発生しない。
実スロットは通常操作のままで、クリックしただけで見本に変わる旧方式は使わない。
テクスチャの追加・変更はせず、見本枠にも仮のバニラスロット画像を使用する。


## Curiosのback装備連携

- 対象：Minecraft 1.21.1、Curios **9.5.1+1.21.1**（任意導入）。Curiosなしでも従来の手持ち・インベントリ収納が使える。
- このMODのデータでプレイヤーへ標準`back`枠を割り当てる。Curiosの既存プリセットを使い、他MODのback枠を加算・上書きしない（データパック等による上位設定は別）。
- Big Bag (`packingcube:large_bag`) のみ装備対象。Filter BagはBig Bag内のモジュールとして引き続き利用する。
- Curios画面の**back実装備枠**へBig Bagを入れ、画面を閉じる。設定したラジアル用キーでメニューを開く（デフォルトC）。操作設定のPackingCubeカテゴリで変更可能。
- 装着中Filter Bagはラジアルメニューから開く。Big Bagの収納画面から右クリックで開く旧操作は削除した。
- 他のGUIを開いている間・カーソルに実アイテムを持つ間・観戦中はキー要求を拒否。装備なしなら何も開かない。
- 自動収納は装備中back→通常インベントリ36枠→通常の拾得処理の順。各Big Bag内は左から右。
- 無効化されたback枠・見た目専用枠は機能対象外。Big Bagを見た目専用枠や別種スロットへ装備することも通常操作では拒否する。
- GUIが開いているルートバッグは装備中でも自動収納から一時除外。装備解除して通常インベントリへ戻してもID追跡し、変更先を移動後の本体へ切り替える。不在・ID重複では編集を止める。
- 背負い表示はユーザー制作モデルと32×32テクスチャを使用する（docs/BACKPACK_RENDERING.md参照）。死亡時の保持・ドロップはCurios設定に従う。

### IDEAで試す

1. この変更版のファイルを適用し、**Gradleを再読み込み**する。開発実行ではCurios本体も自動で依存関係へ入る。
2. `runClient`を起動。Curios画面でBig Bagをbackへ装備し、画面を閉じて、操作設定で割り当てたラジアル用キーを押す。
3. タグ・個別アイテム設定済みのFilter BagをBig Bagへ入れ、画面を閉じて対象アイテムを拾う。

Curios非導入の開発実行はGradleプロパティ`withoutCurios=true`で切り替え可能（例：`./gradlew runClient -PwithoutCurios=true`）。
クライアント／サーバー双方で同じPackingCube更新版を使う。


## ラジアルメニュー

- **Cでラジアルを開く → マウスで方向を選ぶ → 左クリック**で、その位置のFilter Bagを装着したまま開く。Cを離しても決定しない。
- 上がBig Bagの1枠目、そこから時計回りに2〜9枠目。空き枠は詰めず、元のスロット位置と対応を保つ。
- アイコンと枠番号を表示し、選択中バッグの名前を中央に表示。金床などで付けたカスタム名も使う。
- 左クリックまたは数字キー1〜9でも決定できる。C（設定済みラジアルキー）をもう一度押す、右クリック、Esc、インベントリキーで閉じる。中央・空き枠でキーを離した場合は開いたまま。
- 通信待ち中にキーを離していても通常どおり開き、左クリックを待つ。次のラジアルキー押下で閉じる。
- 画面下の**「大かばんの構成」**からBig Bagの装着・取り外し用画面へ進める。手持ちBig Bagの右クリックも同じ構成画面を開く。
- 構成画面のFilter Bag右クリックは、今後は**通常のアイテム移動**。中身を開く操作にはしない。
- 対象Big BagはCuriosの有効back実装備を優先。装備がなければ通常インベントリ36枠で先に見つかったBig Bagを使用する。Curios未導入でも使用可能。
- ラジアル中も対象ルートへの自動収納を一時停止。候補を表示した後のモジュール変更・ルート不在・ID重複・別メニューからの選択要求は拒否する。
- 表示アイコンは種類・カスタム名・フィルター設定だけの専用コピー。収納内容やバッグ識別IDなどは含まない。クリック・Shift・ドラッグ・数字キー・投棄による実アイテム取得は不可。
- 見た目は描画プリミティブと既存アイテムアイコンのみ。新規テクスチャ画像は作成・変更していない。

適用対象は直前のCurios back対応版。変更ファイルを上書きし、Gradleを再読み込みして`runClient`を起動する。
クライアントとサーバーは両方とも同じ更新版を使う。


## キーコンフィグ（独立した2項目）

Minecraft標準の **設定 → 操作設定 → キー割り当て → PackingCube** で設定する。

| 項目 | 初期割り当て | 動作 |
| --- | --- | --- |
| 大かばんを直接開く | B | Big Bagの装着・取り外し用画面を直接開く |
| バッグのラジアルメニューを開く | C | 装着中Filter Bagを選ぶラジアルを開く |

- 大かばんはB、ラジアルはCを初期値にする。旧`key.packingcube.open_back_bag`は引き続き登録しない。
- 好みに応じて各項目を変更できる。他MODの割り当てと重複していないことを確認する。
- 既にキー設定を保存している場合（未割り当てを含む）は保存済み設定を優先する。新しい初期値にするには、この2項目だけリセットするかB／Cを手動設定する。
- 設定の保存・再割り当て・未割り当て・初期化はMinecraft標準の機能を使う。`options.txt`全体を削除する必要はない。
- ラジアルの開閉は設定したキーを追跡する。キーを離す操作は再押下判定のリセットだけに使い、決定しない。マウスボタンやNeoForgeの修飾キー設定にも対応する。
- 同一キー・同一修飾キーを両方へ設定した場合はラジアルだけを実行。別々のキーを同時に押した場合も1回の入力処理ではラジアルを優先し、開く要求を二重送信しない。
- 通常画面ではCuriosの有効back装備を優先し、なければ通常インベントリのBig Bagを使う。バッグ画面内では現在の親Big Bagを維持して切り替える。無関係のGUIやカーソル保持中は画面を置換しない。
- Curios本体や他MODのキーは自動変更しない。他MOD側の重複も標準キー設定で変更する。
- Big Bag画面からFilter Bagへ右クリックで遷移する旧操作は復活させない。

適用対象：直前のラジアルメニュー版。ZIPのファイルを上書きしてGradle再読み込み後、`runClient`でキーを設定する。


## バッグ画面内のB／C操作

デフォルトキーの場合：

| 開いている画面 | B | C |
| --- | --- | --- |
| 通常画面 | Big Bag管理画面を開く | ラジアルを開く |
| Big Bag管理画面 | 閉じる | 同じBig Bagのラジアルへ |
| Filter Bag | 親Big Bag管理画面へ | 親Big Bagのラジアルへ |
| ラジアル | 変更なし | もう一度押すと閉じる |

- Cを押して離すとラジアルが開いたままとなり、有効なバッグ方向を左クリックすると開く。どの方向でもキーを離すだけでは決定しない。もう一度Cで閉じる。
- 長押しのキーリピートを「もう一度押した」と数えない。閉じた直後もキーを離すまでは自動で再オープンしない。
- バッグ切り替え時は開いていたFilter Bagの親を使う。複数のBig Bagがある場合も、別のBig Bagを優先し直さない。
- 単体Filter Bagには親Big Bagがないので、装備／通常インベントリのBig Bagへフォールバック。Big Bagがなければ切り替えない。
- カーソルに実アイテムを持っている間はB／Cで閉じたり切り替えたりせず、先に元へ戻すよう案内する。
- フィルター検索欄に入力フォーカスがある間、B／Cは文字入力として扱う。Escで検索フォーカスを外してから操作する。
- 再割り当てしたキー・マウス・修飾キーを参照するので、B／C固定ではない。

この追加差分の適用対象は、直前のデフォルトB／C版。ファイル上書き→Gradle再読み込み→runClientで確認する。
クライアントとサーバーの両方へ同じ更新版を適用する。

## ラジアルの選択音とフィルターのツールチップ

- ラジアルで選択対象のバッグが変わると、高めのクリック音（バニラUIボタン音、pitch 1.6）をローカル再生。大かばん管理ボタンも対象。同じ対象にいる間は繰り返さず、中央・空き枠への移動は無音。
- 左クリック／数字キーで有効な選択を送るときは、決定用クリック音（pitch 1.8）を一度再生。これは操作音であり、サーバーでの遷移成功を保証する音ではない。
- Filter Bagのアイテムツールチップに、含む／含まないモード、登録タグ（`#namespace:path`）、アイテム名とIDを表示。未登録なら現在のモードで収納する／しない挙動を表示する。
- ラジアルでバッグの方向を選ぶと、同じツールチップを表示する。中央・空き枠には表示しない。
- 長大なツールチップを避け、条件はタグ→アイテム順に最大8件を表示し、残りの件数を案内する。全条件の編集・確認は既存のフィルター画面で行う。
- ラジアルへ同期するのは、最大256件の有効なフィルター設定と種類・カスタム名のみ。収納物や識別IDは同期しない。バッグ本体の保存データや収納判定は変更しない。
- 新しい音声ファイル・テクスチャは不要。音はローカルUI音で、Minecraftの主音量に従う。他プレイヤーには再生しない。

今回の追加差分は「画面内B／C操作」版へ適用する。ZIP上書きとパッチは同じ内容の代替手段。サーバー／クライアントとも更新する。

## バッグ画面のカーソル位置

- ラジアル初期化時の中央移動に加え、位置記憶がある場合はMinecraft標準の中央解放を通らない。
- Big Bag・Filter Bag・ラジアルの切り替えでは、現在のマウス位置を引き継ぐ。
- バッグを閉じてから同じワールドで開き直した場合も、最後にバッグ画面で使っていた位置へ戻す。カメラ操作中の座標は記憶しない。
- 別のGUIからバッグを開く場合は、そのGUIでの現在位置を優先する。
- ウィンドウサイズが変わった場合は相対位置を維持し、画面外へはみ出さないよう補正する。フィルター画面内の設定パネル切り替えではカーソルを移動しない。
- まだ位置を記憶していないワールド初回起動時は、Minecraft標準の位置をそのまま使う。ワールドを変えたら記憶はリセットする。設定ファイルには保存しない。
- 開く直前にカーソルを非表示状態で解放し、内部座標と表示位置を合わせてから表示する。初期化後の復元はしない。閉じてワールド操作へ戻る際のマウス捕捉・カメラ制御はバニラのまま。Minecraft非アクティブ時は独自復元しない。

今回の追加差分は直前の「選択音・フィルターツールチップ」版へ適用する。新しいサーバー通信や保存データの変更はない。

## レジストリ分離・音・datagen・コード整理

- `Packingcube` は起動処理だけにし、アイテム／メニュー／クリエイティブタブの登録を `registry` へ分離した。既存の登録IDとセーブ形式は維持。
- Big Bagが開けたときとCuriosへ装備するときは、バニラの革防具装備音を使う。Big Bagの音は右クリック・B・Filter Bagから戻る・管理ボタンの経路で共通化した。
- フィルター操作番号を `FilterActions` へ集約し、重複していたメニュー起動処理を `BagMenuOpener` へ分離。Javaの書式・importも統一。
- `runData` で単純なアイテムモデルJSONを生成し、レシピ定義を書くためのプロバイダーも追加した。既存の見た目は維持し、新しいテクスチャは作っていない。
- 材料・コストが未指定なので、新規レシピは勝手に確定していない。
- 詳細：[コード構成](docs/ARCHITECTURE.md)／[IDEAでのdatagenと追加方法](docs/DATAGEN.md)。

**今回のZIPを上書きで適用する場合は、旧モデル2ファイルを削除すること。**

- `src/main/resources/assets/packingcube/models/item/large_bag.json`
- `src/main/resources/assets/packingcube/models/item/filter_bag.json`

生成版は `src/generated/resources` に同梱している。Gitパッチで適用する場合、上記削除も自動的に含まれる。適用対象は直前の「カーソル保持」版（PC-13）。ZIPとパッチは代替手段であり二重適用しない。


## ラジアル操作をクリック決定へ統一

Cで開く、左クリックで選択、もう一度Cで閉じる。長押しして離す決定は廃止した。既存の数字キー1〜9による選択、右クリック／Escで閉じる操作、カーソル保持、選択音、フィルター表示は維持している。

今回の差分はレジストリ分離・datagen・コード整理済みのPC-17版へ適用する。追加の削除ファイルはない。


## カーソルが一瞬中央へ戻る不具合の修正

従来の「標準の中央解放→画面初期化で元の位置へ戻す」を廃止した。バッグのadded内で、捕捉中かつ記憶位置がある場合だけ「非表示で解放→内部座標を同期→表示位置を移動→カーソルを表示」と処理する。GUI間の切り替えは現在位置をそのまま使い、最初から位置記憶がない場合だけ標準処理に任せる。

Minecraft内部のマウス状態5フィールドへ触るため、`META-INF/accesstransformer.cfg` を追加している。**適用後は起動中のrunClientを停止し、Gradleを再読み込みしてからrunClientを再起動する。リソースの再読み込みだけでは反映されない。**

今回の差分はPC-18のクリック選択版へ適用する。削除するファイルはない。

## 日本語・英語の翻訳datagen

翻訳は `data/ModLanguageProvider.java` で英語・日本語を一組で定義し、IDEAの `runData` から生成する。生成JSONも同梱しているので初回ビルド時のrunData実行は不要。詳細は `docs/DATAGEN.md`。移行時は手書き側の `src/main/resources/assets/packingcube/lang/en_us.json` と `ja_jp.json` を削除し、生成側と二重管理しない。

## 拾得時のポーチ自動収納

- 自動収納のON/OFFはポーチ単位。バックパック全体のスイッチとボタンは廃止。以前のバックパックOFF値は残っていても無視する。
- ポーチを開いて「設定」から、ポーチ単位の自動収納ON/OFFと優先度（0〜9）を変更する。大きい数から収納する。
- 数値が同じ場合は、有効なCurios back装備→通常インベントリのバックパック位置順→バックパック内の左から右の順。異なるバックパック間でも優先度の数値を先に比較する。
- 条件に一致する有効なポーチへ入る分を収納し、残りを次の対応ポーチ、通常インベントリへ渡す。そこも満杯なら地面に残る。廃棄はしない。
- 含む／含まない・タグ／個別アイテムの既存フィルターが適用される。含む・未登録なら収納しない。OFFは手動収納を禁止する設定ではない。
- 自動収納は地面の拾得物のみ。単体ポーチ、チェストなどからの手動取り出し、直接付与アイテムには適用しない。
- バックパックや内部ポーチを開いている間は、その親バックパックへの自動収納を一時停止する。他の有効なバックパックは利用可能。
- 既存バッグとの互換性のため初期値はON・優先度0。設定はバッグ本体に保存され、取り外し・交換後も維持する。旧バックパック全体設定はポーチの動作へ影響せず、データを消す移行処理も行わない。

## 共通のバッグ設定UI

フィルター設定は再利用可能な `FilterEditorPanel` へ分離した。収納領域の高さとバッグ固有設定の行数を `BagSettingsLayout` へ渡して配置できる。ポーチの自動収納ON/OFF・優先度は共通フィルターから独立したまま。新しいバッグへ組み込む手順と責務は `docs/GUI.md` を参照。

## フィルターモードと自動収納スイッチの関係

- フィルターは「モード: 含む／含まない」のボタン1個で切り替える。登録条件・検索・ページはリセットしない。
- 自動収納はポーチの「このポーチの自動収納」だけで切り替える。ONかつフィルター・容量などを満たせば収納、OFFならそのポーチだけ対象外。
- バックパックの旧全体ON/OFFは参照しない。開いている親バックパックへの一時停止は引き続き適用する。

## ポーチ設定の左右配置とスクロール

左側は収納とインベントリ、右側は見本枠も含む全設定。中央の線は表示しない。高さが足りない場合は右側だけホイール／スクロールバーで移動できる。収まる場合はバーを表示しない。検索・フィルター判定・自動収納条件は変更していない。

## 設定画面の左右別の高さと画像制作

左のポーチ＋インベントリは通常画面と同じ位置・176×132で固定し、横へ設定を開く。右の設定は独立した原点で上下中央に配置し、画面に応じて最大357まで広げる。横幅が足りない場合は左を動かさず、GUIスケールを下げる／ウィンドウを広げる案内を表示する。×ボタンは左領域のヘッダー内。入りきらない右側の内容はスクロールする。ユーザー制作の全GUI／ウィジェット／アイテム画像31枚の仕様は`docs/TEXTURES.md`。この一覧のGUI画像の読み込みは未実装で、画像を置くだけでは反映しない（受領済みのCurios背負いモデルは別途対応済み）。

## Curios装備時の外見

ユーザー制作バックパックの装備用モデルをbackスロットの外見に接続。アイテム表示も同じモデルをparent参照で流用し、インベントリ・額縁・手持ちのdisplay変換はBlockbench側の設定を継承する。生成するラッパーにdisplayは追加しない。Curiosの表示トグルを尊重し、胴体へ追従する。初期位置・防具との重なりは実クライアントで要確認。ファイルと調整箇所は`docs/BACKPACK_RENDERING.md`。

設定画面の上端「設定」を左ドラッグして移動、端・四隅を左ドラッグしてサイズを調整できます。インベントリは固定です。小画面では設定がインベントリに重なって表示され、内容はスクロールできます。同じ画面内では位置とサイズを保持し、画面を閉じると初期状態に戻ります。移動・リサイズ・前面表示は他のMOD画面でも利用できる共通部品で、バニラGUIは変更しません。

ユーザー制作の共通ウィジェット画像20枚を適用。ボタン・選択タブ・ON/OFF・×・検索欄・見本枠・スクロールバーに対応。原本を改変せず、未受領の通常ボタン差分は通常画像を共用。受領一覧と残りの素材はdocs/TEXTURES.md、実装はdocs/WIDGET_SKINS.md。

PC-36でユーザー制作のインベントリ・設定パネル・ラジアル背景も適用。文字は白に統一。テーマ修正は前回20枚のウィジェットと関連コードを含む累積ZIPで配布する。ラジアル枠/ポーチ画像は未受領のため仮表示。

## 手動の一括収納
バックパック管理画面の「一括収納」で、通常インベントリ27枠から装着ポーチへまとめて収納できます。自動収納OFFでも既存のフィルター・優先度に従います。ホットバーや装備は動かさず、残りは元の枠に保持します。カーソルを空にして使用してください。詳細は[操作・仕様](docs/MANUAL_STOW.md)を参照。

## 補充ポーチ
装着した補充ポーチから、指定したホットバー枠・オフハンド・選択中の取引材料を補充します。収納は自由で、フィルターは搬出だけを制限します。対象枠・タイミング・補充後個数・3機能の個別ON/OFFを設定でき、取引の実行は手動です。初期は使い切ったら1スタック、補充フィルターOFF。現在はクリエイティブ欄/giveで取得できます。マルチは全員同じ更新版が必要です。[仕様と確認手順](docs/REFILL_POUCH.md)を参照。

補充設定は「補充先」「補充方法」「補充フィルター」の3ページ。数値は残数の条件と補充後の手元の個数を区別し、必要な項目だけ表示します。動かない場合は調べるアイテムを持って`/packingcube refillstatus`で両手の条件を確認できます。使用前と同じ個数に戻る時にクライアントの見た目が更新されない同期不具合を修正しました。実クライアントでの解消は要確認です。
