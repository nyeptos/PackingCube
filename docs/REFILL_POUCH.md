# 補充ポーチ（PC-45）

## アイテム・収納
- ID: `packingcube:refill_pouch`。1列9枠で、バックパックへ装着・単体で開く・ラジアルから開く操作に対応。ポーチ自体はCurios backへ装備しない。
- 作者の`refill_pouch.png`（16×16）を無加工で使用。レシピ未追加。クリエイティブ欄または`/give @s packingcube:refill_pouch`で取得する。
- **収納にはフィルターを適用しない。** 手動挿入・Shift移動・一括収納のいずれも、収納可能な物を自由に入れられる。バッグ・シュルカーボックス等の入れ子制限は維持する。
- 拾得時の自動収納は行わない。既存の小さな収納ポーチは今までどおり収納フィルター・自動収納を使う。

## 設定画面
名称は「補充フィルター」に統一。設定を次の3ページに分ける。
- **補充先**: ホットバーON/OFF、補充する9枠、オフハンドON/OFF、取引ON/OFF。装着/在庫の必要条件と、クリエイティブでは手元補充しないことを表示。
- **補充方法**: 「手元が0個になったら補充」「手元が指定数以下なら補充」「使うたびに補充」の選択。残数の設定は指定数以下の場合だけ表示。補充後は「手元を1スタックまで補充」か「手元を指定個数まで補充」を選び、指定時だけ個数欄を表示。数は「補充を始める手元の残り個数」と「補充後に手元に持つ個数」を分け、追加する個数ではないと説明する。複数ポーチの優先度は詳細を開いた時だけ表示。
- **補充フィルター**: ON/OFFと目的の説明。OFFでは登録エディターを隠し、ONにすると既存のアイテム/タグ編集が出る。ページ切替やOFFで保存済み登録を消さない。

使わない入力欄は非表示。ページ移動でアイテムの設定は書き換えず、短いページに非表示エディター分の空白スクロール領域を残さない。左のインベントリ・ウィンドウ移動/リサイズ・既存作者画像/音/ボタンアニメーションは維持する。

## 設定と初期値
| 設定 | 初期値・範囲 |
| --- | --- |
| ホットバー補充 | ON |
| 対象ホットバー枠 | 1〜9の全枠ON。ボタンをクリックして個別に切り替え |
| オフハンド補充 | ON。ホットバー補充とは独立 |
| 取引補充 | ON。上記2機能とは独立 |
| 補充する条件 | 手元が0個になったら／手元が指定数以下なら／使うたび。初期は0個になったら |
| 残り個数のしきい値 | 初期16、0〜63。指定数以下モードでのみ有効 |
| 補充後の個数 | 初期1スタック、指定1〜64。実アイテムの上限へ切り詰める |
| 補充フィルター | OFF。ONにすると登録したアイテム・タグの含む／含まないで搬出を制限 |
| 優先度 | 0〜9、大きいものが先 |

タイミング・しきい値・補充後個数はホットバーとオフハンドで共通。取引は常に1回分で、この数量設定を適用しない。補充フィルターは3種類すべての搬出に適用する。

フィルターOFFはすべての在庫が補充候補。登録条件とモードはOFFにしても消さない。有効な「含む・未登録」は何も補充しない。「含まない・未登録」はすべて補充候補。トーテムだけを補充したくない場合は、含まないモードへ`minecraft:totem_of_undying`を登録する。

PC-43の既存hotbar/trade/優先度・登録条件は保持する。新設定がない既存ポーチも上表の初期値で読み、旧収納条件は搬出条件として保存するが、補充フィルターをONにするまで制限しない。旧版の「毎回、使用前の個数へ戻す」から、初期挙動は「使い切ったら1スタック」に変わる。

## 補充元と複数ポーチ
装着した補充ポーチだけを使い、通常ポーチ・単体ポーチ・チェストは使わない。同優先度ならCurios有効back→通常インベントリのバックパック順→モジュール左から右。現在開いているバッグの親を別writerで書き換えず、1処理で親ビューは一つ。

各ポーチの対象枠・ON/OFF・補充フィルター・タイミングを満たすものだけが候補。最初の在庫がある候補が補充後個数の上限を決め、不足は下位候補から補う。下位ポーチ自身の個数上限も超えない。例: 上位は8個・在庫2、下位は32個なら合計8個まで。上位がフィルターで対象外なら下位の設定を使う。

## ホットバー・オフハンド
- 実際の使用イベント（ブロック/アイテム/対象/部位指定の右クリック、直接UseItemOnBlock、非耐久アイテムの消費、食事等の使用完了）から、使用した手のスロットを記録し、次のサーバーPost tickで実際の個数減少を確認する。
- ホットバーの対象指定は「使用した選択中枠を補充してよいか」。指定した他の空き枠へ勝手に配らず、ホットバー全体を常時満タンにする機能ではない。
- オフハンドは独立して同じタイミング・数量ルールで補充する。両手の使用記録は別々に保持する。
- トーテム消費は`LivingUseTotemEvent`も起点とし、死亡回避後に補充する。専用ON/OFFはなく、通常の補充フィルターで許可/除外する。
- 同じアイテム・全コンポーネント一致の在庫だけを使う。名前/データ違い、使用後の空瓶・バケツ等の別アイテムを上書きしない。
- 手動移動だけでは発動せず、Q投棄時は使用記録を破棄する。持ち替え/未指定スロット/消費なし/1tick超の古い記録も対象外。
- 生存・非観戦・非クリエイティブ、通常inventoryMenu、空カーソルが必要。弓が別枠から使う矢、耐久値だけの変化、他MOD独自の消費経路は対象を保証しない。
- タイミングは実際の消費を起点に評価する。ポーチへ後から補給しただけで過去の空き枠を埋め直すものではない。同一tick内の複雑な手動操作との競合は実機確認が必要。

## 取引
- 現在の有効なバニラMerchantMenuで、選択中レシピ・現在価格・売り切れを確認し、入力2枠へ1回分の不足だけ補充する。
- 異種の手動入力は触らず、供給元も全コンポーネント一致。両材料をフィルター込みで事前確保できる場合のみ移す。同じ材料が2枠にあっても二重予約しない。
- 結果取得・自動売買・使用回数の加算は行わない。
- 終了時はバニラの通常返却に任せ、ポーチへ自動で戻さない。実NPC/画面終了/独自取引画面は実機確認が必要。
- PC-43で追加したMerchantMenu/Containerへの限定AT読取りを継続し、バニラGUIや取引実行処理は書き換えない。

## UI・保存・通信
- 既存の浮動・リサイズ・前面表示・スクロール部品を流用。左インベントリ位置は固定、右設定の長いページだけスクロール。新画像は不要、既存の作者テクスチャ/音/ボタン演出/白文字を維持。
- `RefillSettingsView`は画面ローカルのページ・詳細表示を管理し、`RefillSettingsPanel`はAccess経由で同期値/設定要求を受ける独立UI。通常収納ポーチの共通フィルター編集は変更しない。
- `CUSTOM_DATA.packingcube_refill`にhotbar/trade/offhand/filter/slots/timing/threshold/targetを保存。slotsはホットバー9bit、offhandは別bool、target=0は1スタック。優先度と登録条件は既存形式。
- FilterActionsの既存0〜8は維持し、9=SET_REFILL_OPTIONを追加。サーバーで現menu/所有/種別/field/value/数値範囲を検証し、保存・同期する。ラジアル見本には上限検証済み設定だけコピーし、収納/IDはコピーしない。
- 通信バージョンは3。サーバーと全クライアントを同じ更新版にする。

## 実機チェック
1. PC-43版へパッチ適用後runClientを完全再起動。補充ポーチの右側設定で9枠・オフハンド・タイミング/数量・補充フィルターを確認。3ページを切り替え、小画面でスクロール/ドラッグ/リサイズ/文字/ホバーも確認。
2. 含む/含まない/無効のどれでも自由に収納でき、搬出だけが設定に従うこと。フィルター切替で登録が消えないこと。
3. 指定/未指定ホットバーとオフハンドでブロック/松明/食料を使い、使い切り/しきい値/毎回、指定個数/16個上限の投擲物/不足/複数優先度を確認。
4. トーテムを許可/除外して消費。別のMODの死亡回避や消費経路との競合を確認。
5. 手動移動/Q投棄/持ち替え/空瓶/名前違いでは誤補充しないこと。取引は1回分の材料のみで売買は手動、入力/終了返却も確認。
6. 取り外し/再装着/ワールド再起動/Curiosなし/実マルチで保存と同期を確認。

GameTestはサーバー状態/消費イベント/資源/レイアウト計算の検証であり、実クライアントの描画/入力/実NPC/マルチの確認とは別。


## 「補充されない」報告: 同期不具合の再現と修正
通常サバイバルの最後のブロック設置・食事完了のサーバー数量だけでは再現できなかったが、クライアント予測を模したContainerSynchronizerのスロットミラーを加えると、次の2件が修正前に失敗した。
- メインハンド16→15個を補充で16へ戻すと、サーバー最終数は16でもミラーが15のまま。
- オフハンド最後の1個を消費し、補充で1へ戻すと、サーバー最終数は1でもミラーが空のまま。

原因は`broadcastChanges`が最終スロットを最後に送ったスロットと比較し、同数・同componentだと更新を送らないこと。補充成功時、対象のremote baselineだけを消費直後の状態に更新してからバニラの差分同期を行い、必ず対象枠の訂正を送る。全インベントリの強制再送や毎tickの余分な送信はせず、状態ID管理もバニラ同期に任せる。ホットバーはInventoryMenu36〜44、オフハンドは45。収納側/補充数量/安全条件は変更しない。

これはユーザーの実クライアント環境を直接確認したものではないため、適用後の実機再確認が必要。ほかの原因を切り分けるため、調べるアイテムを手に持ち、画面を閉じて`/packingcube refillstatus`を実行すると、両手についてクリエイティブ/装着対象なし/同一データ在庫なし/補充フィルターによる除外/空枠で見本なし/実使用待ち等を表示する。自分の状態を読むだけで、収納・補充・設定変更はしない。チート権限不要。

PC-45では直接ItemStack.useOn、部位指定インタラクト、非耐久アイテムの消費イベントも補足。独自MODの任意の消費経路を保証するものではない。実クライアント/NPC/マルチは未確認。

## PC-46: 補充先のスロット選択GUI（補充処理拡張とは別段階）

- 設定の「補充先を選択」でモード切替。同じ枠で左ボタンを離すと指定/解除。
  別枠へドラッグして離した場合は取消。完了ボタンまたはEscで終了。
- 指定中は通常のアイテム移動、Shift移動、数字キー交換、Q投棄、F交換を抑止。
  カーソルにアイテムがある場合は開始できない。上段のポーチ収納9枠は対象外。
- 中央のインベントリ27枠とホットバー9枠は既存位置を維持。
  右側は防具（頭・胴・脚・足）とオフハンド、左側は有効なCurios機能スロット。
  左右は表示・指定用で、装備の着脱画面ではない。
- Curiosの種類別アイコンを直接参照し、表示順でなく種類IDとindexで保存。
  5枠を超える場合はホイール/スクロールバーで移動。無効・消滅した枠は表示・指定不可。
  保存済み指定を別の枠へ振り替えない。Curios未導入時は左欄を出さない。
- 作成者提供のequipment_panel / curios_panel / refill_target_selected / hovered / pressed
  を使用。防具とオフハンドの空きアイコンはバニラ参照。
  アイテムや枠の拡縮なしで枠の透過度を遷移させ、ホバー/押下/確定音を付ける。
- 保存済み指定を設定スナップショット・ラジアルプレビューに反映。
  既存ホットバー/オフハンドの補充処理はその指定に従う。
- **今回、新規のインベントリ・防具・Curios指定は保存と表示まで。これらへの
  実際の補充や、最初から空の枠への自動補充は未実装。** 取引補充は従来通り。
  空き枠へ入れる品目を「ポーチ内順」か「枠別の非消費見本」で決めるかは未決定であり、
  勝手に品目を割り当てない。次段階でこの仕様と安全な搬出処理を実装する。
- ネットワークversion 4。クライアント/サーバーで同じ版を使用する。
